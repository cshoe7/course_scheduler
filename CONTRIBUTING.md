## Branching  
1. Branch naming: feature/short-description or fix/short description
2. Never commit directly to main
3. Keep branches short-lived — aim to merge within a few days
## Pull Requests
4. Every change goes through a PR — no direct pushes to main
5. PR title should be descriptive: what changed and why. Include in the description:
     - What this PR does
     - How to test it manually
     - Any known limitations or follow-up work
6. At least **one approval** required before merging.
7. The author merges (after approval) — not the reviewer.
## Code Style
8. Python
9. Naming: camelCase for variables and functions, PascalCase for classes and components
